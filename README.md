# OAuth Path

Look up an app and get a shareable guide to registering its OAuth app and getting it approved: how hard it is, how long it takes (hands-on time and waiting time shown separately), the requirements that trip people up, what to do when blocked, and which steps an agent can do versus which need a person.

- **Library:** 4 hand-checked guides chosen because each is hard in a different way: GitHub (self-serve), Slack (manual review queue), Google/Gmail (scope-driven verification and security assessment), LinkedIn (application-only access).
- **Live generation:** type any app name or website. An agent searches the web, reads sources, and builds a guide in real time with a shareable link.

## Run it

```bash
npm install
cp .env.example .env.local      # then put your key in .env.local
npm run dev                     # http://localhost:3000
```

Needs Node 20+ and two keys for live generation, both in `.env.local`:

| Variable | Used for | Get it at |
|---|---|---|
| `OLLAMA_API_KEY` | the model that plans searches and writes the guide (default `gemma4:31b`, override with `OLLAMA_MODEL`) | https://ollama.com/settings/keys |
| `TAVILY_API_KEY` | the web search (Tavily's free plan: 1,000 credits a month, no card) | https://tavily.com |

Why two: Ollama's own web search needs paid credits, so search is done by Tavily and Ollama only writes. Without both keys, live generation answers 503 and the library still works. Notion and Shopify guides have been generated live this way (reported by the author; see VERIFICATION.md).

```bash
npm test         # 27 tests, no network or key needed
npm run build    # production build
```

Optional: `GUIDE_STORE_DIR` (where generated guides are saved), `GENERATE_LIMIT_PER_HOUR` (default 6 per visitor).

## Key decisions

1. **One schema for everything** (`lib/types.ts`). Curated and agent-made guides share a shape, validated with zod. Model output is never trusted unvalidated.
2. **Two kinds of time.** Hands-on setup and waiting on the provider are separate fields, because they plan completely differently.
3. **Every claim carries evidence:** `official`, `third-party` or `uncertain`, with numbered sources. Conflicts between sources are listed in the guide, not hidden.
4. **Evidence audit on live guides** (`auditSources` in `lib/agent.ts`). Any source URL the agent cites that its search never returned is flagged, and claims resting only on such sources are downgraded to `uncertain`.
5. **Agent versus human is explicit per step** (`agent` / `either` / `human`), answering "where do I take over?".
6. **Honest about testing.** Each guide states whether anyone created the OAuth app. None did.
7. **Progress is streamed** (server-sent events) so the user watches searches happen instead of waiting on a spinner.
8. **One shared pipeline, one small adapter per provider.** `lib/agent.ts` only talks to the `ResearchProvider` interface (`lib/providers/types.ts`): `research()` searches and writes notes, `formatGuide()` turns notes into JSON. Only an Ollama adapter exists today (it runs the searches through Tavily and gives the model the results); another provider means writing one more adapter. The pipeline validates with zod, repairs once, audits, and sets `slug`, `meta` and `attemptedSetup=false` itself.

How the claims in the four guides were checked, corrected, or left unconfirmed is in [`VERIFICATION.md`](./VERIFICATION.md).

## Limitations

- **No OAuth app was created or submitted.** That needs real accounts, logins, 2FA and business details. Guides rest on provider documentation, and say so.
- **Live testing so far is small:** two apps (Notion, Shopify), with the links checked but not every claim. Both services need credits or have free-tier limits, and the default model name (`gemma4:31b`) came from Ollama's docs; `OLLAMA_MODEL` overrides it.
- **Live guides are only as good as what the search finds.** The agent can miss a page or misread one. The audit catches invented links, not misreadings, so every claim shows its sources.
- **Generated guides are stored on local disk** (`lib/store.ts`). On serverless hosts such as Vercel the disk is temporary, so share links to live guides can expire. Swap `saveGuide`/`loadGuide` for a database to fix this.
- **Rate limiting is in memory** (`lib/rateLimit.ts`): it resets on restart and is not shared across instances.
- **Scope:** 4 curated guides, not 100. The library is a hard-coded array; at scale it would be generated by the same agent, reviewed by a person, and stored in a database.
- Provider rules change. Each guide shows its research date.

## Layout

```
app/page.tsx                 home: search + library
app/guide/[slug]/page.tsx    one guide (curated or generated)
app/api/generate/route.ts    streams the agent's progress
components/                  SearchBox (client), GuideView, CopyLink
lib/types.ts                 the Guide schema
lib/library.ts               the 4 curated guides
lib/agent.ts                 the shared pipeline + evidence audit (provider-independent)
lib/providers/               types.ts (the interface), ollama.ts (the adapter), search.ts (Tavily),
                             index.ts (getProvider), prompts.ts, errors.ts
lib/store.ts, rateLimit.ts, sse.ts
tests/                       unit tests + a MockProvider end-to-end test of the pipeline (no network)
```
